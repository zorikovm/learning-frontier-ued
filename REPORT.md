# Поиск границы обучения в JaxUED

## Задача

В UED уровни для student выбирает отдельный teacher. Если давать слишком простые уровни, обучение почти ничего не меняет. Если давать слишком сложные, student не получает полезных траекторий. Нужны уровни около текущей границы его возможностей.

Student зафиксирован: исходный PPO + LSTM из JaxUED. Менялись только оценка уровней, replay, история уровней и мутации. Полный бюджет одного запуска равен 30000 updates, или 245760000 шагов среды.

## Baseline

- **DR** обучается на каждой новой случайной партии уровней.
- **PLR-down** сначала оценивает новые уровни без обновления PPO, сохраняет их в буфер, а PPO обновляет только при replay.
- **ACCEL** после replay дополнительно создает и оценивает измененные варианты выбранных уровней.

В исходном PLR вероятность replay после заполнения половины буфера равна 0.8. Вероятность выбора уровня складывается из ранга оценки с весом 0.7 и давности последнего посещения с весом 0.3. Размер буфера равен 4000.

## Проблема MaxMC и PVL

MaxMC и PVL измеряют ошибку value function на текущей траектории, но не ожидаемую пользу следующего обновления PPO. Поэтому большую оценку могут получить:

- уже освоенный уровень с неточной value function;
- слишком сложный уровень с шумной оценкой;
- случайно удачная траектория, после которой результат не повторяется.

На коротком запуске PVL почти полностью выбирал уже решенные уровни: доля успеха среди верхних 10% оценок была 0.975. Корреляция PVL с изменением успеха после следующего PPO update оказалась отрицательной: -0.492. Значит, большая текущая ошибка сама по себе плохо находит границу обучения.

## Метод

### MNA

MNA перенесен из DEGen. Он строится по отрицательной части многошагового TD-сигнала и обнуляется, пока уровень ни разу не был решен. Это отсеивает уровни, на которых student пока вообще не получает полезных траекторий.

MNA используется только для teacher. PPO по-прежнему получает обычные GAE advantages и targets.

### История успеха

Для каждого уровня teacher хранит:

- сглаженную частоту успеха `p`;
- число посещений;
- число завершенных и успешных эпизодов;
- максимальную полученную награду.

Начальное значение `p=0.5`. После прохождения уровня:

$$
p_{new}=p_{old}+0.3(p_{obs}-p_{old}).
$$

Величина

$$
4p(1-p)
$$

максимальна при `p=0.5` и уменьшается для почти всегда решаемых и почти всегда нерешаемых уровней. Это дешевая версия идеи SFL: отдельная модель и дополнительный набор траекторий не нужны.

### Итоговая оценка

$$
S = \operatorname{MNA}\left(4p(1-p)+0.25\max(p_{new}-p_{old},0)\right).
$$

Чистый множитель `4p(1-p)` оказался слишком жестким: уровень быстро терял приоритет после первых успехов. Добавка с коэффициентом 1.0, наоборот, слишком сильно выделяла случайно удачные прохождения. Поэтому был проверен один промежуточный коэффициент 0.25. Перебора по проверочной выборке не проводилось.

После расчета оценки используется обычный механизм PLR: ранжирование, учет давности и замена элементов буфера не менялись.

## Проверочная выборка

Public уровни не использовались для выбора метода. Для этого отдельно зафиксированы 64 случайных лабиринта 13x13: по 16 уровней с 15, 25, 35 и 45 стенами. Seed генерации — `20260823`, seed оценки — `20260824`, по пять попыток на уровень.

Эта выборка создается через исходный `make_level_generator`. Она не попадает в буфер, не используется как родитель мутаций и не меняет поток случайных чисел обучения.

## Эксперименты

Сначала проверены исходные DR, PLR и ACCEL на 250 updates. Затем отдельно сравнивались MaxMC, PVL, MNA, оценка по частоте успеха, изменение успеха, их произведения и два варианта мутаций. Полный журнал, включая отрицательные результаты, находится в `EXPERIMENTS.md`.

### Сравнение по трем seeds, 250 updates

| Метод | Проверочная выборка | Связь оценки с текущим успехом | Успех среди верхних 10% |
|---|---:|---:|---:|
| PLR MaxMC | 0.2521 ± 0.0346 | 0.540 ± 0.012 | 0.349 ± 0.047 |
| PLR MNA | 0.2615 ± 0.0191 | **0.311 ± 0.052** | **0.219 ± 0.035** |
| MNA + граница обучения | **0.2865 ± 0.0377** | 0.342 ± 0.035 | 0.272 ± 0.055 |

Новый вариант обошел MaxMC на каждом из трех seeds. Средняя парная разница равна `+0.0344 ± 0.0031`. На этом бюджете все методы имеют нулевой результат на public уровнях.

### Сравнение на 1000 updates, seed 0

| Метод | Public | Проверочная выборка | Средняя награда на ней |
|---|---:|---:|---:|
| PLR MaxMC | 0.0250 | 0.8469 | 0.6407 |
| PLR MNA | **0.0375** | 0.8406 | 0.6573 |
| MNA + граница обучения | 0.0250 | **0.8531** | **0.6680** |

По числу стен:

| Метод | 15 | 25 | 35 | 45 |
|---|---:|---:|---:|---:|
| PLR MaxMC | 0.9625 | 0.8750 | 0.8375 | **0.7125** |
| PLR MNA | **0.9750** | 0.8750 | 0.8375 | 0.6750 |

На public уровнях ненулевой результат получен только на SixteenRooms: 0.2 для MaxMC, 0.3 для MNA и 0.2 для нового метода. Остальные семь уровней пока не решаются. Разница в один успех из десяти слишком мала для вывода.

## Что видно по выбранным уровням

MNA слабее связан с текущим успехом, чем MaxMC, и выбирает более длинные пути. Но его условие «уровень хотя бы раз решен» может слишком рано отбрасывать трудные лабиринты с редкими успехами. Это видно по группе с 45 стенами, где MaxMC пока лучше.

Чистая оценка `4p(1-p)` действительно выбирает промежуточную область, но сама по себе ухудшает обучение. Нужен и сигнал качества траектории, поэтому умножение на MNA работает лучше.

На 1000 updates средняя частота успеха среди уровней с наибольшей итоговой оценкой стала 0.493. То есть к этому моменту teacher действительно сосредоточился около промежуточной сложности. При этом метод не задает точную цель `p=0.5`: на выбор также влияют величина MNA, ранг и давность.

## Проверенные упрощения

- Только `4p(1-p)`: 0.2125 на проверочной выборке, хуже MaxMC.
- `MNA * 4p(1-p)`: 0.2375, слишком быстро понижает приоритет освоенных уровней.
- Коэффициент изменения успеха 1.0: 0.2844, но сильнее смещен к удачным траекториям.
- Коэффициент 0.25: 0.2906 на seed 0 и 0.2865 в среднем по трем seeds.
- ACCEL с MNA: 0.2031, хуже PLR с MNA.
- Адаптивное число мутаций: улучшило ACCEL с 0.1594 до 0.2281, но все равно проиграло PLR.

## Ограничения

- На полном бюджете 30000 updates запусков пока нет.
- Сравнение на 1000 updates проведено только для seed 0.
- Короткие запуски используют сжатое расписание learning rate и не являются первыми шагами полного запуска.
- Случайная проверочная выборка заметно проще самых трудных public лабиринтов.
- Текущих данных недостаточно, чтобы утверждать превосходство над PLR или ACCEL по итоговой zero-shot оценке.
